## Findings
- **MEDIUM** Перемещение методов в специализированный класс обоснованно
  - *Location*: WhiteLabel.php, AbstractLabel.php
  - *Description*: Правильный рефакторинг - специфичные методы (работа с миграциями и языками) перемещены из AbstractLabel в конкретный класс WhiteLabel. Это улучшает разделение ответственности.
- **MEDIUM** Добавлены guards для обработки не-WhiteLabel случаев
  - *Location*: UserPlanListBuilder.php:149, UserPlanFunnelStepMatcher.php:67
  - *Description*: В UserPlanListBuilder (строка 149-151) и UserPlanFunnelStepMatcher (строка 67-72) добавлены проверки instanceof. UserPlanListBuilder возвращает fallback, UserPlanFunnelStepMatcher выбрасывает исключение - логика различается. Нужно убедиться, что оба подхода соответствуют требованиям бизнеса.
- **LOW** Хорошее покрытие edge cases
  - *Location*: UserPlanListBuilderTest.php, UserPlanFunnelStepMatcherTest.php
  - *Description*: Добавлены тесты для обоих сценариев обработки не-WhiteLabel labels. Тест UserPlanListBuilderTest корректно проверяет fallback логику, тест UserPlanFunnelStepMatcherTest проверяет исключение.
- **LOW** Стоит использовать более предметное исключение вместо RuntimeException
  - *Location*: src/Service/User/UserPlan/UserPlanFunnelStepMatcher.php:67
  - *Description*: В случае неконсистентных данных сейчас выбрасывается общее RuntimeException. Для сервисного слоя и последующей диагностики лучше использовать доменное исключение (например, связанное с отсутствием WhiteLabel у реселлера), чтобы упростить обработку ошибки и сделать поведение более предсказуемым.
- **INFO** Рефакторинг методов языков
  - *Location*: src/Entity/WhiteLabel/WhiteLabel.php
  - *Description*: Методы getLanguages, getLanguage и getDefaultWhiteLabelLanguage перемещены из AbstractLabel в WhiteLabel, что логично для специфичной функциональности.
- **MEDIUM** Проверка типа в сервисах
  - *Location*: src/Service/Api/ListBuilder/User/UserPlanListBuilder.php
  - *Description*: В UserPlanListBuilder и UserPlanFunnelStepMatcher добавлены проверки instanceof WhiteLabel перед вызовом методов. Рекомендуется использовать полиморфизм вместо проверок типов, если возможно.
- **INFO** Тесты покрывают новые проверки
  - *Location*: tests/Service/Api/ListBuilder/User/UserPlanListBuilderTest.php
  - *Description*: Добавлены тесты для проверки поведения при разных типах лейблов, что улучшает покрытие.
- **MEDIUM** Несоответствие обработки ошибок между сервисами
  - *Location*: src/Service/Api/ListBuilder/User/UserPlanListBuilder.php:150, src/Service/User/UserPlan/UserPlanFunnelStepMatcher.php:67
  - *Description*: В UserPlanListBuilder при отсутствии WhiteLabel выполняется ранний возврат с переводом заголовка (строка 150-152), тогда как в UserPlanFunnelStepMatcher выбрасывается RuntimeException (строка 67-71). Это приводит к непоследовательному поведению: часть функционала работает с SystemeLabel, а другая — завершается ошибкой.
- **MEDIUM** EAGER-загрузка может вызвать проблемы с производительностью
  - *Location*: src/Entity/WhiteLabel/WhiteLabel.php:16
  - *Description*: В новом классе WhiteLabel используется fetch: 'EAGER' для отношения whiteLabelLanguages. Это может привести к N+1 запросам при загрузке множества сущностей WhiteLabel, особенно в списках.
- **LOW** Недостаточное покрытие тестами сценария с не-WhiteLabel
  - *Location*: tests/Service/User/UserPlan/UserPlanFunnelStepMatcherTest.php:605
  - *Description*: Тест RuntimeException в UserPlanFunnelStepMatcherTest проверяет только случай, когда getOwnLabel() возвращает null, но не тестирует случай, когда возвращается не-WhiteLabel (например, SystemeLabel).
- **INFO** Рефакторинг типов лейблов: перенос методов языков и миграций в WhiteLabel
  - *Location*: src/Entity/WhiteLabel/AbstractLabel.php, src/Entity/WhiteLabel/LabelInterface.php, src/Entity/WhiteLabel/WhiteLabel.php
  - *Description*: Методы работы с языками и миграциями (getLanguages, getLanguage, getDefaultWhiteLabelLanguage, getCurrentMigration) удалены из AbstractLabel и LabelInterface и перемещены в конкретный класс WhiteLabel. В измененных сервисах (UserPlanListBuilder, UserPlanFunnelStepMatcher) добавлены проверки instanceof для безопасного доступа. Это улучшает инкапсуляцию, но требует внимания к другим субклассам AbstractLabel, чтобы они не зависели от удалённых методов.
- **INFO** Защита типа в UserPlanListBuilder с fallback на перевод
  - *Location*: src/Service/Api/ListBuilder/User/UserPlanListBuilder.php
  - *Description*: В методе getUserPlanTitle добавлена проверка, что метка владельца является WhiteLabel. Если нет, возвращается переведённый заголовок плана через translator. Это корректно обрабатывает случай SystemeLabel и других типов лейблов.

  - *Location*: src/Service/User/UserPlan/UserPlanFunnelStepMatcher.php
  - *Description*: Метод findFunnelStep выбрасывает RuntimeException, если метка не WhiteLabel. Рекомендуется заменить на доменный исключительный тип (например, WhiteLabelException) для ясности и лучшей обработки на верхних уровнях.
- **INFO** Добавлены unit-тесты для новой логики
  - *Location*: tests/Service/Api/ListBuilder/User/UserPlanListBuilderTest.php, tests/Service/User/UserPlan/UserPlanFunnelStepMatcherTest.php
